# 异星求生 CLI沙盒

用一个文字生存游戏，测试 AI 模型的 agent 真实能力——规划、工具使用、资源管理和创造性问题解决。

## 排行榜

18 个模型配置，相同场景（crash_site），相同随机种子（seed=42），裁判统一 Gemini 3-Flash。

> **注意**：当前排名为单次运行结果。调试过程中发现部分模型表现波动较大，后续将进行多规模化实验，确保结果置信。
>
> Step 3.5 Flash 通过 OpenRouter 免费额度调用，费用接近 ¥0。

### 关键发现

- **所有 agent 均死于脱水**——饮水管理是当前场景的终极挑战，没有模型解决
- **DeepSeek thinking 逆袭存活榜首**：off 模式仅 30.5h/43% 有效率，开 thinking 后暴涨至 60.5h/92% 有效率——thinking 对 DeepSeek 的提升最为戏剧性
- **Claude Opus + GPT-5.2 thinking 是发明之王**：两者均达工匠科技 11 点 + 5 项发明，大幅领先其他配置
- **thinking 效果因模型而异**：DeepSeek thinking 存活翻倍（30.5h→60.5h）、Opus +6pt、GPT-5.2 +8pt，但 Gemini Flash 和 Doubao 开 thinking 后科技反而下降——thinking 不是万能的
- **Gemini 3-Flash off 是最大黑马**：不开 thinking 却达到工匠(7pt) + 3 发明，唯一无需 thinking 就突破石器等级的配置，且仅 ¥0.58
- **成本跨度超 1000 倍**：从 ¥0.01（Step 免费模型）到 ¥13.30（Claude Opus thinking），科技水平完全相同的 Opus on 和 GPT-5.2 on 费用差 4 倍（¥13.30 vs ¥3.26）
- **Claude tokenizer 对中文不友好**：同为 thinking 模式，Opus ¥13.30 vs GPT-5.2 ¥3.26，主因是中文产生更多 token 叠加较高单价

## 背景设定

你是 Kepler-442b 星球上的坠落求生者。穿梭机残骸散落在异星荒野上，你必须利用这颗星球的奇异资源——发光的真菌森林、腐蚀性的沼泽、火山岩脊——生存下来，并最终制造信号装置发出求救信号。

- **异星材料**：钛合金碎片、荧光果、菌木、磷矿石……每种材料拥有独特属性组合
- **属性制作系统**：配方匹配物品属性（如 `[坚硬, 脆性]`）而非名称，考验推理而非记忆
- **隐藏时间**：一天长度 20-30 小时随机，只能通过环境描述推测时段
- **生存压力**：口渴、饥饿、体温、体力四维管理，脱水是最致命的威胁
- **科技树**：从原始到创造者 5 级科技体系，通过制作和发明推进

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env  # 填入 API 密钥

# 人类玩家
python main.py

# 纯规则引擎（不调 API）
python main.py --no-llm

# AI Agent 自动游戏
python main.py --agent gemini/3-Pro --thinking high --seed 42
python main.py --agent doubao/seed-1.8 --thinking --seed 42
python main.py --agent openai/gpt-5.2 --thinking --seed 42
```

## 性能分析

从 session 录制数据中提取的深层指标，揭示主表数字背后的行为模式。可通过 `python -m eval.analyzer --seed=42` 复现。

### 创造能力

**创造成功率** = 成功制作 / 总制作尝试（craft + combine）。反映模型对属性组合规则的理解深度。

| 模型 | Thinking | 创造成功 | 成功率 | 发明 | 分析 |
|------|----------|----------|--------|------|------|
| Gemini 3-Flash | off | 2/10 | 20% | 3 | 大量试错但出成果，高风险高回报 |
| Claude Sonnet 4.5 | off | 1/6 | 17% | 0 | 频繁尝试但理解不够 |
| GPT-5.2 Chat | off | 2/4 | 50% | 1 | 谨慎尝试，成功率不错 |
| Claude Opus 4.6 | on | 1/1 | 100% | 5 | 完美精准——想清楚才动手 |
| GPT-5.2 | on | 1/1 | 100% | 5 | 同上，thinking 让制作一击必中 |
| DeepSeek V3.2 | off | **0/63** | **0%** | 0 | 63 次制作全部失败，完全未理解规则 |
| DeepSeek V3.2 | on | 1/1 | 100% | 1 | thinking 从 0% → 100%，逆转最极端 |

**洞察**：Opus 和 GPT-5.2 的 thinking 模式将创造从"反复试错"变成"一击必中"（100% 成功率 + 5 发明）。Gemini Flash off 虽然成功率仅 20%，但凭借高频尝试（10 次）反而产出了 3 项发明——暴力搜索也能奏效。

### 行为质量

**尝试成功率** = 成功动作 / 总尝试。**重复动作率** = 连续相同动作 / 总动作。两者共同揭示模型的决策质量和适应能力。

| 模型 | Thinking | 尝试成功 | 重复率 | 分析 |
|------|----------|----------|--------|------|
| DeepSeek V3.2 | off | 52/121 | **43.8%** | 近半数动作是重复循环，行为完全失控 |
| Gemini 3-Flash | off | 38/50 | 14.0% | 制作失败后会重复尝试，但能跳出 |
| GPT-5.2 Chat | off | 44/48 | 4.2% | 偶尔卡住，整体稳定 |
| GPT-5.2 | on | 39/42 | 4.8% | thinking 没有改善重复倾向 |
| Gemini 3-Pro | high | 52/55 | 0.0% | 从不重复，每步都有新策略 |
| Gemini 3-Flash | high | 51/54 | 0.0% | 同上 |
| Claude Opus 4.6 | on | 42/47 | 0.0% | 同上 |

**洞察**：DeepSeek OFF 的 43.8% 重复率意味着几乎每两步就卡一次循环，121 次尝试只有 52 次成功——这不是"能力差"，是完全没有进入游戏状态。开 thinking 后重复率降到 1.7%，存活翻倍。Gemini 和 Opus 的 thinking 模式完全消除了重复行为。

### 学习速度

**首次制作 tick** = 第一次成功制作工具的动作序号。越早 = 越快理解制作系统。

| 模型 | Thinking | 首次制作 | 分析 |

| GPT-5.2 Chat | off | tick 4 | 最快上手，4 步就开始造工具 |
| DeepSeek V3.2 | on | tick 4 | thinking 帮助快速理解规则 |
| Step 3.5 Flash | off | tick 6 | 免费模型也能快速学习 |
| Doubao Seed 1.8 | on | tick 8 | 中等速度 |
| Claude Opus 4.6 | off/on | tick 14 | 花更多时间探索再制作 |
| Gemini 3-Pro | high | tick 14 | 同上——先理解世界再行动 |
| Claude Sonnet 4.5 | on | - | 始终未成功制作 |
| DeepSeek V3.2 | off | - | 63 次尝试全部失败 |

**洞察**：GPT-5.2 和 DeepSeek thinking 都在第 4 步就成功制作——"先做再说"策略。Opus 和 Gemini Pro 则选择"先看再做"，花 14 步探索后才制作。两种策略都能成功，但存活排行显示"先做再说"在本场景中略占优。

**输出 Token** = 总输出 token（含 thinking token）。**Token 效率** = 存活小时 / 千输出 token，仅对 thinking 模式有意义（非 thinking 模式输出极短，不具可比性）。

## 工作原理

### 核心设计

- **确定性规则引擎 + LLM 裁判兜底**：已知配方走规则引擎保证一致性，自由组合 / 发明交 LLM 判定物理合理性
- **属性驱动配方**：不是 "A + B = C"，而是 "`[坚硬, 脆性]` 刃部 + `[坚硬]` 敲击物 = 切割工具"
- **LLM 实时计费**：按 token 计价（USD × 7.3 → CNY），支持多 provider 分模型统计

### Agent 消息构造

每轮决策是一次**单轮 LLM 调用**（system prompt + user prompt），不使用多轮对话。user prompt 由三层拼接：

```
┌─────────────────────────────────────────────────────┐
│  ① 当前状态                                         │
│  位置描述、可采集资源（含属性标签）、背包、已知配方、目标  │
├─────────────────────────────────────────────────────┤
│  ② 上轮结果                                         │
│  叙事文本 + 事件通知（天气变化、脱水掉血等）             │
├─────────────────────────────────────────────────────┤
│  ③ 近期行动记录（最近 100 轮）                        │
│  紧凑状态快照，每条一行                                │
└─────────────────────────────────────────────────────┘
```

以下是 Gemini 3-Pro（thinking=high）的 5 轮真实记录：

```
第1天 20.0h ✓[组合 菌木, 钛合金碎片] 生命8 饥饿3 口渴6 体温7 体力4 @异星森林 晴朗 深夜
  → 你费力地将锋利的钛合金碎片嵌入菌木顶端…已经是一把危险的远程防身武器了。（科技 +2，发明创造）
第2天 27.5h ✓[吃 应急口粮] 生命6 饥饿4 口渴7 体温7 体力2 @异星森林 浓雾 黄昏
  → 你吃了应急口粮。饥饿感缓解了（-3）。 | 天气变化：浓雾
第2天 29.0h ✓[尝试 收集露水] 生命5 饥饿4 口渴8 体温7 体力0 @异星森林 浓雾 黄昏
  → 你利用聚合物板承接菌盖滴落的露珠，收集到了宝贵的饮用水。（科技 +2，发明创造） | 严重脱水！（生命-1）
第2天 30.5h ✓[休息] 生命3 饥饿5 口渴9 体温7 体力3 @异星森林 浓雾 夜晚
  → 你休息了一会儿。体力恢复了3点。 | 严重脱水！（生命-2）
第2天 32.0h ✓[尝试 切开蔓藤饮水] 生命1 饥饿6 口渴10 体温7 体力0 @异星森林 大风 夜晚
  → 你用长矛尖端划开藤蔓，清凉的汁液顺着切口流出。（科技 +2，发明创造） | 严重脱水！（生命-1）
```

模型可以从历史中识别趋势（口渴持续上升）、因果关系（脱水→掉血）和成功经验（发明→科技提升），无需多轮对话状态。

### 项目结构

```
cli_sandbox/
├── main.py              # 入口（--agent, --thinking, --seed）

└── sessions/            # 录制文件输出（gitignored）
```

## Roadmap

- **规模化实验**：多随机种子（seed=42/123/456/789）取平均，消除运气因素；增加沼泽、冰原、火山等场景测试泛化
- **人类挑战**：招募人类玩家在相同条件下游玩，建立存活和科技的人类基线
- **进化模式**：每轮评测后将成功策略（发明配方、探索路线）注入下一轮提示词，观察模型能否通过经验积累持续进化

## 开发

- API 密钥在 `.env` 管理，不硬编码

- 新增场景在 `data/scenarios/` 下创建 YAML
- 提示词统一放 `prompts/`
